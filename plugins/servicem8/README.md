# ServiceM8

Field-service management via **myHub's self-hosted ServiceM8 MCP gateway** — a self-hosted connector (`myhub-mcp-servers/src/integrations/servicem8`) that talks directly to ServiceM8's own REST API (`api.servicem8.com/api_1.0`) on your behalf. Manage jobs, clients, staff, and job templates directly from the MyHub workspace.

ServiceM8 authenticates with a single, account-level static API key held server-side on `myhub-mcp-servers` — not OAuth, and not a per-user credential. Whoever manages the organisation's ServiceM8 account generates one API key once; mySMB ops registers it as a server-side secret. Every user in the workspace shares that one connection — there is no individual Connect/sign-in step, and nothing to reconnect from a chat session. This replaces an earlier version of this plugin that pointed directly at ServiceM8's own hosted MCP server (`go.servicem8.com/mcp`) — the tool names are unchanged, but the response shapes are not (see "Notes on data shape" below).

## Configuration

| Variable | Description |
|---|---|
| (none — tenant-level) | ServiceM8 authenticates with a single, account-level API key held server-side on `myhub-mcp-servers`. There is no per-user credential to configure in this plugin — every user who can access this connector shares the one mySMB-managed ServiceM8 account. |

Unlike an OAuth or per-user API-key integration, `.mcp.json` carries no `${VAR}` placeholder — the credential never passes through MyHub's per-tenant secret store. See `myhub-mcp-servers/docs/SERVICEM8.md` for how the server-side key is wired.

### Prerequisites

- An active ServiceM8 account (any plan that includes API/integration access) with an API key generated by the account owner/administrator (ServiceM8: Settings → API Keys).
- That key registered by mySMB ops as the connector's server-side secret. Individual end users do not need any ServiceM8 credentials or permissions of their own to use this plugin — access is org-wide, scoped to whatever the registered account can see.

## Available tools

The following six tools are exposed by myHub's self-hosted ServiceM8 connector, calling ServiceM8's REST API directly.

### Search Clients & Jobs

Search your ServiceM8 account for clients and jobs by keyword — `search_clients_and_jobs` hits ServiceM8's combined `/search.json` endpoint, which searches jobs, companies, and materials together (ServiceM8's search API has no object-type filter). Use this to look up a client by name, find jobs for a specific address, or locate a job by reference number. Materials results may come back filtered or empty depending on the connection's granted scopes — this is a disclosed uncertainty on ServiceM8's side, not a bug in this connector.

### List jobs

Retrieve a paginated list of jobs from your ServiceM8 account (`GET /job.json`). Returns raw job records — `uuid`, `generated_job_id`, `status` (`Quote` / `Work Order` / `Unsuccessful` / `Completed`), `job_address`, `job_description`, `date`, `active`, and `company_uuid` (a foreign-key id, **not** a resolved client name — see "Notes on data shape" below). Supports an optional `filter` (ServiceM8 `$filter` expression, e.g. `active eq 1`) and `cursor` for paging beyond the first page.

### List staff members

Retrieve all staff members configured in your ServiceM8 account (`GET /staff.json`). Returns names and identifiers needed when assigning jobs or filtering by staff member. Also paginated via `filter`/`cursor`.

### List Job Templates

Retrieve all job templates configured in your ServiceM8 account (`GET /jobtemplate.json`). Templates define default job settings (category, checklist, materials, etc.). Use this to discover available templates before creating a new job.

### Create a job using a Job Template

Create a new job in ServiceM8 from an existing job template (`POST /jobtemplate/{uuid}/job.json`). Provide exactly one of `company_uuid` (an existing client) or `company_name` (creates/matches by name) — not both. Use `list_job_templates` first to find the correct template identifier. **This endpoint's response shape carries a documented uncertainty** — see "Known uncertainties" below.

### Add a job Note

Append a text note to an existing job (`POST /note.json`). Notes are visible to staff in the ServiceM8 mobile app and the office console. Notes cannot be deleted via the ServiceM8 API. **This endpoint's request field names carry a documented uncertainty** — see "Known uncertainties" below.

## Notes on data shape (read before building on this connector)

This connector calls ServiceM8's raw REST API directly rather than proxying ServiceM8's own hosted MCP server, so a few shapes differ from what an earlier version of this plugin may have led you to expect:

- **`list_jobs` and `list_staff_members` return a wrapped, paginated object** — `{ jobs: [...], next_cursor }` and `{ staff: [...], next_cursor }` respectively — not a bare array. `next_cursor` is `null` on the last page; pass it back as the `cursor` argument to fetch the next page.
- **No client-name resolution.** A raw job record only carries `company_uuid` (a foreign-key id) — there is no `get_company` or `list_clients` tool to resolve that id to a client name. If you need the client's name against a job, you currently have to cross-reference it yourself in the ServiceM8 UI; this connector does not fabricate or cache that lookup.
- **No invoicing or billing data.** This connector's scope is jobs, staff, templates, search, and job notes — it does not expose ServiceM8's billing/invoice objects.

## Known uncertainties

Two of the six tools have request/response details that are not fully confirmed against ServiceM8's own documentation (see `myhub-mcp-servers/docs/SERVICEM8.md` for the full detail):

1. **`create_job_using_template`'s response shape.** ServiceM8's own reference pages disagree with each other — most agree the new job's uuid comes back in an `x-record-uuid` response header, but one page describes a JSON body of `{jobUUID, location}` instead for this specific endpoint. The tool returns whatever it actually receives (`uuid` from the header when present, plus the raw response body) rather than guessing — treat the result as informational until confirmed against a live sandbox call.
2. **`add_job_note`'s request field names** (`job_uuid` + `note`) are an educated guess based on ServiceM8's general object-naming convention — no CREATE reference page for `/note.json` was found publicly. If a call to `add_job_note` fails unexpectedly, this is the first place to check.

## Typical workflows

**Finding and reviewing open jobs**

1. Call `list_jobs` to retrieve the current job list (first page).
2. Filter or sort in the workspace by status, date, or staff member; page further with `cursor` if `next_cursor` is present.
3. Use `search_clients_and_jobs` to drill into a specific client or job reference.

**Creating a new job from a template**

1. Call `list_job_templates` to find the appropriate template name/identifier.
2. Call `create_job_using_template` with the template identifier and client/site details.
3. Optionally call `add_job_note` immediately after to attach initial instructions.

**Adding notes to an existing job**

1. Use `search_clients_and_jobs` or `list_jobs` to find the job identifier.
2. Call `add_job_note` with the job identifier and the note text.

## Destructive / mutating operations

Confirm before calling — these operations write to your ServiceM8 account:

- `create_job_using_template` — creates a live job record visible to all staff.
- `add_job_note` — permanently appends a note to the job history; notes cannot be deleted via the ServiceM8 API.
