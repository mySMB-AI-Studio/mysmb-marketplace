# Hammerjack client operations

Complete the installing user's Hammerjack setup, choose the existing Sprout Employee and Time & Attendance accounts, and review employee mappings and company attendance rules. Credentials stay in Connections. Never guess a Sprout system ID from an employee number.

Client staffing stays in the platform employee-to-client assignments. Raw identity mappings and run diagnostics stay organisation-only; client management Records tables are isolated to the authenticated portal and are read-only to its members. Their dashboard tiles consume the validated snapshot projection, not the raw Records widget bridge.

Review and publish each draft automation explicitly. Run verified real synchronization before scorecards or reports. No source mapping should synthesize missing leave balances, absent/late statuses or a score without a review. The historical mock use case is a manual synthetic demo with a separate source, an explicit synthetic portal and a default-off setup flag.

Monthly Performance Reviews creates one shared monthly form and a request per staffed employee/client primary contact. Scorecards weight attendance 10% and the numeric review average 90%; show no score before review. Monthly Client Report PDF Generator reads the platform published Monthly Report and saved portal metrics, and uses bundled template and fonts. Save generated PDFs in each portal's Monthly Reports folder.

Do not run HR connector writes, payroll operations, real customer demos, grant changes or automatic publication as installation side effects.
